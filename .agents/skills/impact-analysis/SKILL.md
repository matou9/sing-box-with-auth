# 变更影响分析

## 分析流程

### Step 1: 识别修改目标
确认要修改的文件和函数/类型

### Step 2: 查找直接引用
```bash
# 查找函数/类型的所有引用
grep -rn "函数名\|类型名" --include="*.go" .

# 查找包的所有导入方
grep -rn '"github.com/sagernet/sing-box/被修改包路径"' --include="*.go" .
```

### Step 3: 评估影响层级
- **L1 直接影响**：直接使用被修改代码的文件
- **L2 间接影响**：使用了 L1 文件中相关功能的文件
- **L3 构建影响**：因构建标签可能受影响的文件

### Step 4: 生成影响报告
```
## 影响分析报告

### 修改目标
- 文件: xxx
- 变更: xxx

### 直接影响 (L1)
- file1.go: 使用了被修改的函数 X
- file2.go: 实现了被修改的接口 Y

### 间接影响 (L2)
- file3.go: 通过 file1 间接依赖

### 需要同步修改的文件
1. xxx
2. xxx

### 需要运行的测试
- go test ./被修改的包/...
- go test ./依赖的包/...

### 风险评估
- 高/中/低
- 原因：xxx
```

## 高危模块清单
以下模块的修改需要特别谨慎的影响分析：
| 模块 | 原因 | 影响范围 |
|------|------|----------|
| adapter/ | 核心接口 | 所有协议 + 路由 |
| common/dialer/ | 底层网络 | 所有网络连接 |
| route/router.go | 路由核心 | 所有连接的路由决策 |
| dns/ | DNS 核心 | 所有域名解析 |
| box.go | 启动入口 | 整个系统 |
